# ToolStack

ToolStack is a Next.js App Router project for a user-first online tools library. The current starter contains 12 working browser-side utilities, seven category routes, global search, a configurable Google AdSense Auto ads integration, and generated sitemap/robots routes. Tool inputs are not sent to an application server by the implemented tools.

## Local Development

```powershell
npm install
npm run dev
```

Open http://localhost:3000. Run `npm run lint` and `npm run build` before deployment.

## Configuration

Copy `.env.example` to `.env.local` and set `NEXT_PUBLIC_SITE_URL` to the canonical HTTPS origin, without a trailing slash. The value is used for canonical metadata, structured data, sitemap and robots output. `NEXT_PUBLIC_ADSENSE_CLIENT_ID` enables the site-wide Google AdSense Auto ads loader; leave it unset until the site is approved and the required consent message is published. The configured publisher ID is public and is not a secret.

## Adding A Tool

1. Add a `ToolDefinition` to `src/lib/tools.ts` with a unique slug, category, description, title, supporting text, steps, FAQs and relevant tool slugs.
2. Add the tool behavior to `src/components/tool-workbench.tsx`. A catalog entry alone does not create a working tool.
3. Add a unique visual glyph/color as needed, and verify the category, homepage search, related links, metadata and sitemap.
4. Run `npm run lint` and `npm run build`, then manually test normal, invalid and empty inputs.

Category counts, tool routes, metadata, related links and sitemap entries are generated from the catalog. Empty categories are noindex and excluded from the sitemap until they contain a working tool.

## Production And Hostinger

1. Select a Hostinger Node.js deployment that supports the Next.js 16 runtime requirements (Node.js 20.9 or newer).
2. Connect `quicktools-online.com` to the Hostinger app, enable HTTPS, and set `NEXT_PUBLIC_SITE_URL=https://quicktools-online.com` in the app environment. Configure and approve the site in AdSense, publish an appropriate consent message, then set `NEXT_PUBLIC_ADSENSE_CLIENT_ID` to the `ca-pub-...` client ID.
3. Install dependencies with `npm ci`, build with `npm run build`, and start with `npm run start` using the host's Node.js application settings.
4. Verify `https://quicktools-online.com`, `/ads.txt`, `/sitemap.xml`, `/robots.txt`, canonical URLs, and generated tool pages after DNS and HTTPS are active.

The sitemap is generated by `src/app/sitemap.ts` from tools and non-empty categories. No separate sitemap command is needed. Confirm the deployment mode supported by the selected Hostinger plan before launch.

## Launch Checklist

- AdSense Auto ads is wired but stays disabled unless `NEXT_PUBLIC_ADSENSE_CLIENT_ID` is set. The configured publisher ID is taken from the account screenshot; configure and approve the website in AdSense first, then enable the desired side rail and anchor ad formats in the Auto ads settings. Google controls actual positions and may not fill every placement.
- Publish a Google-certified consent message in AdSense Privacy & messaging before serving ads to visitors in the EEA, UK, or Switzerland. The application does not implement its own consent-management platform.
- `public/ads.txt` declares the configured AdSense publisher. Verify it is reachable at `/ads.txt` after deployment.
- Update and review the privacy policy, including the operator, hosting, retention, jurisdiction, contact details, and advertising disclosures, before launch.
- Privacy and terms copy are launch drafts. Add the operator, hosting, retention, jurisdiction and contact details and have the wording reviewed.
- `quicktools-online.com` is the selected production domain. Confirm contact details before launch.
